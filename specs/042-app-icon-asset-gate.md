# App Icon Asset Gate

## Objective

Move PakFit closer to store-ready Android and iOS packaging by committing branded app icon assets and proving they remain wired into both platform application targets.

## Requirements

- Android manifest must reference `@mipmap/ic_launcher`.
- Android manifest must reference `@mipmap/ic_launcher_round`.
- Android adaptive icon XML files must use the PakFit foreground mark and background color.
- iOS must include `Assets.xcassets/AppIcon.appiconset`.
- iOS AppIcon set must include iPhone, iPad, and `ios-marketing` icon slots.
- iOS AppIcon PNG files must match the pixel dimensions declared in `Contents.json`.
- Xcode Debug and Release build settings must set `ASSETCATALOG_COMPILER_APPICON_NAME = AppIcon`.
- Xcode Resources phase must include `Assets.xcassets`.
- CI and local release validation must run the same app icon asset gate.
- Release evidence must record Android icon status, iOS icon status, and app icon gate status.
- Android and iOS version metadata must be bumped for release artifacts generated by this packaging slice.

## Boundaries

- This gate does not replace final store graphic review, brand review, Play Console listing assets, or App Store Connect listing assets.
- The iOS icon generator is deterministic and local; it does not fetch remote assets or require external design services.
- Future brand refreshes must update committed icon assets, regenerate release evidence, and keep this gate passing.

## Acceptance Criteria

### Scenario: Android launcher icon is packaged

Given the release validation command runs
When Android manifest and launcher icon resources are inspected
Then adaptive and round launcher icons are present
And the Android manifest references both icon resources.

### Scenario: iOS AppIcon catalog is packaged

Given the release validation command runs
When the iOS AppIcon asset catalog is inspected
Then iPhone, iPad, and marketing icon slots are present
And each committed PNG matches the declared icon dimensions.
