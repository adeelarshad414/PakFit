# Spec 034 - Gradle Dependency Verification

## Objective

Improve PakFit's supply-chain integrity by committing Gradle dependency verification metadata and requiring strict SHA-256 verification for resolved Android/plugin artifacts during release validation and CI.

## Functional Requirements

- The repository must include `gradle/verification-metadata.xml`.
- Verification metadata must enable metadata verification and include SHA-256 artifact checksums.
- Local release validation must fail if verification metadata is missing, does not verify metadata, or does not include SHA-256 checksums.
- Android release validation must run Gradle with `--dependency-verification strict`.
- Dependency inventory generation must run Gradle dependency tree tasks with `--dependency-verification strict`.
- CI must run Android release tasks with `--dependency-verification strict`.
- Release evidence must record verification metadata path, byte size, SHA-256, component count, checksum count, and strict mode status.
- Android and iOS version metadata must be bumped for the release artifacts generated by this verification slice.

## Non-Functional Requirements

- Verification must work offline once dependencies are already resolved in the local/CI Gradle cache.
- Verification must not require signing secrets, Play Console access, analytics keys, backend services, or cloud health data.
- New dependency additions or upgrades must intentionally update verification metadata.
- Live vulnerability advisory scanning remains separate from artifact checksum verification.

## Acceptance Evidence

- `gradle/verification-metadata.xml` contains SHA-256 checksum entries.
- `scripts/validate-release.sh` checks verification metadata and runs Gradle in strict dependency-verification mode.
- `scripts/generate-dependency-inventory.sh` runs dependency tree tasks in strict dependency-verification mode.
- `.github/workflows/pakfit-ci.yml` runs Android build tasks with `--dependency-verification strict`.
- `scripts/generate-release-report.sh` records verification metadata evidence.
- `bash scripts/validate-release.sh` passes locally.

## Release Boundary

This slice proves artifact checksum verification for resolved Gradle dependencies. It does not prove that dependencies are free of known vulnerabilities; live advisory scanning still requires a network-enabled scanner or hosted dependency review service.
