# Platform Compatibility Gate

## Objective

Keep PakFit's Android and iOS platform metadata aligned with current store-readiness expectations and local build capability before APK/AAB artifacts and iOS release evidence are accepted.

## Requirements

- Android `compileSdk` must be 35 or higher.
- Android `targetSdk` must be 35 or higher.
- Android `minSdk` must remain 26 or higher for the current encrypted local storage baseline.
- The local Android SDK must include the platform matching `compileSdk`.
- GitHub Actions must install Android API 35 platform/build tools before release gates run.
- iOS `IPHONEOS_DEPLOYMENT_TARGET` must remain 16.0 or higher for SwiftUI/PhotosPicker workflows.
- iOS `SWIFT_VERSION` must remain 5.0 or higher.
- Release evidence must record Android SDK metadata, iOS deployment/Swift settings, and platform compatibility gate status.
- Android and iOS version metadata must be bumped for release artifacts generated by this compatibility slice.

## Current Store Context

- Google Play requires new apps and app updates to target Android 15, API level 35, or higher starting August 31, 2025.
- Apple requires App Store Connect uploads to be built with Xcode 26 or later using an iOS/iPadOS 26 SDK or later since April 28, 2026.

## Boundaries

- This gate proves source/build metadata and local Android SDK readiness.
- This gate does not prove Play Console upload acceptance, App Store archive signing, App Store Connect upload, or legal/store review completion.
- Full App Store archive validation remains blocked until Xcode.app, signing assets, and App Store Connect access are available.
- Android Gradle Plugin support for API 35 is covered by `specs/045-android-build-toolchain-gate.md`.

## Acceptance Criteria

### Scenario: Android target API is Play-ready

Given the release validation command runs
When Android Gradle settings are inspected
Then `compileSdk` is at least 35
And `targetSdk` is at least 35
And the matching local Android SDK platform is installed.

### Scenario: iOS deployment metadata stays compatible

Given the release validation command runs
When iOS Xcode project settings are inspected
Then deployment target is at least 16.0
And Swift version is at least 5.0.
