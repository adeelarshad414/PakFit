# Food Photo Privacy Gate

## Objective

Keep PakFit's food photo feature production-safe by proving that captured food images remain preview-only and are not persisted or uploaded in the current local-first build.

## Requirements

- Android photo capture must continue to use preview-only capture through `ActivityResultContracts.TakePicturePreview`.
- iOS photo controls must remain explicit picker/camera flows in the app source.
- Release validation must fail when app source introduces image-byte persistence patterns such as bitmap compression, file output streams, media-store writes, photo byte fields, or upload/client patterns.
- Release evidence must record food photo capture mode and photo privacy gate status.
- Android and iOS version metadata must be bumped for the release artifacts generated by this privacy-hardening slice.

## Boundaries

- This gate is a static release guard, not a substitute for a full privacy/security review of a future vision model or backend.
- Future real image recognition, segmentation, backend upload, analytics, or cloud storage requires a new spec, privacy policy review, store disclosure update, and threat-model update.
- This gate must not require signing secrets, Play Console access, backend services, analytics keys, or cloud health data.

## Acceptance Criteria

### Scenario: Photo bytes are not persisted or uploaded

Given the release validation command runs
When Android and iOS app sources are inspected
Then preview-only photo capture remains present
And image-byte persistence or upload patterns fail the gate.

### Scenario: Release evidence records photo privacy posture

Given release artifacts have been built
When `bash scripts/generate-release-report.sh` runs
Then the report records food photo capture mode and photo privacy gate status.
