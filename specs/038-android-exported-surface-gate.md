# Android Exported Surface Gate

## Objective

Reduce Android attack surface by proving that PakFit exposes only the launcher activity in the current local-first build.

## Requirements

- Android release validation must inspect `app/src/main/AndroidManifest.xml`.
- The manifest must export exactly one component: `.MainActivity`.
- `.MainActivity` must declare the `MAIN` action and `LAUNCHER` category.
- Services, receivers, providers, and activity aliases are not allowed in this release slice.
- CI must run the same Android exported surface gate before accepting release evidence.
- Release evidence must record exported component count, exported component policy, and gate status.
- Android and iOS version metadata must be bumped for the release artifacts generated by this security-hardening slice.

## Boundaries

- Future app links, background services, broadcast receivers, content providers, widgets, or shortcuts require a new spec, threat-model update, manifest review, and release evidence update.
- This gate must not require signing secrets, Play Console access, backend services, analytics keys, or cloud health data.

## Acceptance Criteria

### Scenario: Non-launcher exported components fail release validation

Given the Android manifest declares an exported component other than `.MainActivity`
When `bash scripts/validate-release.sh` runs
Then validation fails before release evidence is accepted.

### Scenario: Release evidence records exported surface

Given release artifacts have been built
When `bash scripts/generate-release-report.sh` runs
Then the report records exported component count, exported component policy, and exported surface gate status.
