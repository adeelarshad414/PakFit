# Android Permission Privacy Gate

## Objective

Reduce mobile privacy risk by making Android permission scope explicit, minimal, and testable for PakFit's current online calorie search and food photo capture workflows.

## Requirements

- Android release validation must inspect `app/src/main/AndroidManifest.xml`.
- The current Android manifest may declare only:
  - `android.permission.INTERNET`
  - `android.permission.CAMERA`
- The manifest must keep `android.hardware.camera` declared with `android:required="false"` so users without camera hardware can still install the app.
- CI must run the same Android permission privacy gate before accepting release evidence.
- Release evidence must record declared permissions, permission count, permission policy, and camera feature posture.
- Android and iOS version metadata must be bumped for the release artifacts generated by this privacy-hardening slice.

## Boundaries

- This gate does not prove runtime privacy behavior for future backend APIs, analytics, ads, push notifications, or account sync.
- Any future permission must be introduced through a spec update, user-facing privacy review, release evidence update, and store privacy disclosure review.
- This gate must not require signing secrets, Play Console access, backend services, analytics keys, or cloud health data.

## Acceptance Criteria

### Scenario: Release validation rejects permission creep

Given the Android manifest declares a permission outside the approved set
When `bash scripts/validate-release.sh` runs
Then the validation fails before release evidence is accepted.

### Scenario: Release evidence records permission posture

Given release artifacts have been built
When `bash scripts/generate-release-report.sh` runs
Then the report lists declared Android permissions, the declared permission count, and the optional camera hardware posture.
