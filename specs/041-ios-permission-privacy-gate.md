# iOS Permission Privacy Gate

## Objective

Reduce iOS store-review and privacy risk by making camera/photo purpose strings explicit, food-photo scoped, and release-gated for PakFit's current photo-assisted calorie estimate workflow.

## Requirements

- iOS Debug and Release build settings must include `NSCameraUsageDescription`.
- iOS Debug and Release build settings must include `NSPhotoLibraryUsageDescription`.
- Both purpose strings must mention PakFit, food photo use, and visible calorie estimation.
- iOS project metadata must not add any other `NS*UsageDescription` key without a reviewed privacy spec.
- iOS app/core Swift sources must not introduce unreviewed permission-sensitive APIs such as microphone, location, contacts, HealthKit, Bluetooth, speech, NFC, or direct photo-library authorization.
- CI and local release validation must run the same iOS permission privacy gate.
- Release evidence must record camera/photo purpose-string status and iOS permission privacy gate status.
- Android and iOS version metadata must be bumped for release artifacts generated by this privacy-hardening slice.

## Boundaries

- This gate does not replace App Store privacy questionnaire review or legal review.
- This gate does not add HealthKit, location, contacts, microphone, Bluetooth, speech, NFC, background modes, analytics, accounts, or backend sync.
- Future permission-sensitive features require a spec update, user-facing privacy review, store disclosure update, and release evidence update.
- This gate must not require signing secrets, App Store Connect access, backend services, analytics keys, or cloud health data.

## Acceptance Criteria

### Scenario: iOS photo permissions stay food-photo scoped

Given the release validation command runs
When iOS project metadata is inspected
Then camera and photo library purpose strings are present in Debug and Release settings
And each purpose string stays product-specific and food-photo scoped.

### Scenario: iOS permission creep is blocked

Given iOS project metadata or Swift sources introduce an unreviewed permission-sensitive surface
When the iOS permission privacy gate runs
Then validation fails before release evidence is accepted.
