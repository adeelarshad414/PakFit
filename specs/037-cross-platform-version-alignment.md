# Cross-Platform Version Alignment

## Objective

Keep PakFit's Android APK/AAB and iOS application metadata aligned so release candidates have one clear product version across platforms and artifacts.

## Requirements

- Android `versionName` must match iOS `MARKETING_VERSION`.
- Android `versionCode` must match iOS `CURRENT_PROJECT_VERSION`.
- Android debug and release APK metadata must match Android source version metadata after build.
- Local release validation must fail before release evidence is accepted when version metadata drifts.
- CI must run the same source and built-artifact version checks.
- Release evidence must record Android source version, iOS project version, built APK metadata, and alignment status.
- Android and iOS version metadata must be bumped for the release artifacts generated by this release-management slice.

## Boundaries

- This gate does not replace Play Console track validation, App Store archive signing, or store listing version review.
- This gate must not require signing secrets, Play Console access, backend services, analytics keys, or cloud health data.

## Acceptance Criteria

### Scenario: Source version metadata stays aligned

Given Android and iOS source version metadata drift
When `bash scripts/validate-version-alignment.sh` runs
Then the validation fails before release builds run.

### Scenario: Built Android metadata matches source

Given Android debug and release APK metadata exists
When `bash scripts/validate-version-alignment.sh --include-built-metadata` runs
Then built Android versionName and versionCode match the Android and iOS source metadata.
